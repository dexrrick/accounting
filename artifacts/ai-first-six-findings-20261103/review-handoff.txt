## Changes and before/after behavior

1. The abbreviated Dr/Cr posting boundary now covers slash and conjunction forms, including both supplied bypasses. Journal generation and calculations remain owned by the existing engine.
2. Unresolved applications cannot borrow a conditional phrase to authorize a later categorical conclusion after adversatives, inherited-subject conjunctions or result clauses. Natural condition-first, can-if, uncertainty-only and negative-unless wording remains usable. Verified issues can still receive definitive conclusions.
3. IRAS fallback passages retain the original issue ID. When a plan exists, fallback requires its validated context owner and matching subject, operation, domain, population and authority. Multiple passages remain associated with that same issue. No-owner evidence is not assigned to a convenient planned issue; the legacy whole-query path remains when no issue scope exists.
4. Workstream/context-owned missing facts constrain their issue. A supported GST conclusion survives a separate unresolved CPF issue. Genuinely unowned material facts remain conservatively question-wide.
5. Numerical verification recognizes cardinal/ordinal deadlines and written currency amounts. Faithful paraphrases can proceed to independent model assessment when typed values, units, currency, arithmetic sign, assertion polarity, local labels, event anchors and temporal relationships match. Deterministic output fields remain strict. Reused source numbers cannot authorize a new calculation or unrelated statutory figure.
6. AI-first advisory receives relevantChatHistory. Production-entry tests exclude prior invoice facts for an independent new accounting request and retain them for a genuine follow-up.

Generation instructions now prioritize the direct client answer, issue-specific application, confident supported conclusions and practical next steps. Independent assessment instructions require full numerical and legal context. No accounting rules, statutory rates, approved-source registries, dependencies or deployment configuration changed.

Main files: src/services/evidenceGroundedSynthesis.ts; src/services/geminiService.ts. Tests extend test_evidence_grounded_synthesis.mjs and test_ai_first_advisory_phase1.mjs, add test_synthesis_numeric_provenance.mjs and test_synthesis_practical_answers.mjs, and register the new suites in scripts/run_all_tests.mjs.

## Remaining concerns and review focus

The architecture remains model generation, independent model support assessment and targeted repair. Numerical matching is a conservative boundary check, not a proof of semantic entailment. Inspect condition scope, negative equality versus valid bounds, event/date direction, multi-passage provenance and issue/population ownership. Check that valid supported answers are preserved, not merely that malicious examples are rejected.

The five-authority practical suite proves that hand-authored supported application claims reach the answer without generic gap warnings.
