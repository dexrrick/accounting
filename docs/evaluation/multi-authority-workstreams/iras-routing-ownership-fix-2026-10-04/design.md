## Owning layer and bounded design

The independent raw-query inventory is correct to recognize a broad routing topic and a specific topic. Reconciliation is incorrect to require a separate material issue for every such overlapping topic regardless of taxonomy/scope. Subject wording currently determines whether the umbrella gets an owner.

Use explicit routing-parent taxonomy relationships for individual-relief topics, independent of the exact failing phrase. A routing-only parent can be owned by a mapped child only within the same requested scope. Require the parent in the independent query inventory, an actual mapped child, registry relationship, matching governing authority/domain and bounded raw-query request scope. Unrelated topics or provider-supplied hints cannot establish ownership.

Record derived routing ownership explicitly on the reconciled issue; it is neither contextual authority nor substantive mapped evidence coverage. Preserve existing evidence gates, source text, retrieval, claim verification and application status. Independent generic relief asks require their own semantic representation. A canonical child subject that happens to contain the umbrella's lexical keywords must not hide a separately omitted general request.

For a recognized routing umbrella, examine bounded query scopes using shared query/request fragmentation. A child-scoped fragment may be represented by its actual mapped child. A generic parent fragment cannot be assigned to that child merely because the child appears elsewhere. Ambiguous/unrepresented scope remains fail-closed. This is not global routing-only suppression; unowned parents and every independently missing substantive topic still create UNASSIGNED_QUERY_TOPIC.
