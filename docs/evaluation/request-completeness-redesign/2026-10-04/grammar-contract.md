# Bounded request language v0 — supervisor decisions

Population clarification: cases21/23/24 lack company-specific facts, so population is UNKNOWN. Do not infer NONRESIDENT for the generic royalty rule in23/24. The qualified subjects in14/15 remain COMPANY, and14 explicitly requires NONRESIDENT. Generic and qualified aliases must retain this distinction rather than adding qualifications from a related fixture.

Actor clarification: case14 COMPANY is the payer; nonresident recipient is a counterparty qualifier, never an alternative actor population. Case19 fund-manager entity type is unspecified (UNKNOWN); case20 investment is a subject, not an actor population (UNKNOWN). UNKNOWN matches only UNKNOWN. In05/07, CPF eligibility does not explicitly say compulsory; COMPULSORY is required only where the question contains that qualification. The prototype must not inject it from a neighbouring alias.

The subject title `CPF relief for employees` describes a beneficiary role and is compatible with either an INDIVIDUAL claimant or an EMPLOYEE general-rule request. The independently parsed request still decides population and the binding must match it exactly. This title must not force EMPLOYEE when `I`/`they` explicitly requests individual eligibility. This bounded title compatibility is not a population wildcard; employee-versus-employer contribution actors remain distinct. Alias constraints must distinguish actors from beneficiaries/counterparties, rather than applying a word-wide population rule.

Core-binding clarification: an outcome with no additional mandatory facets still requires a valid dimension-matched, span-contained binding. Empty represented facets mean omission only when that outcome requires additional facets. Compatible bindings satisfy core representation separately from facet coverage; duplicate core bindings for a zero-facet outcome remain redundant precision failures. A consumed connector without a following request is unknown/incomplete raw inventory (UNCERTAIN), never a valid terminal. Productions must end on token boundaries, so concatenated words cannot impersonate a connector. Nonstring raw input must return UNCERTAIN safely, never throw.

Subject consistency: independent subject-alias validation must also retain any actor/qualification explicitly encoded in the subject text. `employee CPF contributions` cannot claim EMPLOYER population; `employer CPF contributions` cannot claim EMPLOYEE. A neutral contribution alias can use an explicit population field. Explicit nonresident royalty text must preserve NONRESIDENT and cannot satisfy a broader unqualified royalty request. Typed fields cannot override contradictory subject text. A wrong dimension or span cannot contribute core/facet coverage even when another finding already makes the overall result fail. Missing-outcome/facet diagnostics must therefore remain independently accurate. Literal binding spans must be nonempty.

This grammar is a feasibility language, not a universal English parser. The builder must publish its complete declarative productions and bounded alias table in the evaluation module. Tests may not supply grammar entries, parsed outcomes or fixture IDs. No authority/topic/evidence fields participate in parsing.

Input limit: 2,000 UTF-16 code units; at most 12 outcomes. Lexing is case-insensitive and accepts whitespace runs; offsets always refer to original input. Hyphens in declared aliases may accept ordinary hyphen or whitespace, but no arbitrary word deletion, stemming or substring matching. Unsupported modifiers and negation are not stripped. Subjects match complete noun phrases within an anchored production; trailing unknown text cannot be swallowed by `.*`.

```
document := [context] request (connector request)* [terminal]
connector := '.' | '?' | ',' 'and' | 'and' | ',' 'plus' | 'plus'
terminal := '.' | '?'
request := head subject [declared-tail]
         | coordinated-calculation
         | alternative-decision
         | interaction
         | context-reference-treatment
```

Connectors are accepted only between complete recognized requests. Subject phrases may contain conjunctions or alternatives owned by their production. `including` is a scope modifier within an overview, not a request separator. A broad overview plus specific request is distinct from an overview requiring an example. Commas/punctuation alone cannot invent an outcome.

Allowed ordinary heads: `explain` (explain); `explain the general` / `what are the general ... rules` (general explain); `can I claim` / `what can they claim for` (eligible); `how much ... can I claim for` / `how much ... must the employer contribute` / `what does the employer have to pay into` (calculate); `I need an overview of` / `what ... categories are available` (overview explain); `can this person obtain` (eligible); `is the company subject to` (eligible); `when is ... due` (filing, DEADLINE facet); `must ... be filed` (filing, OBLIGATION facet); `how should ... be accounted for` (treatment); `is it tax deductible` (eligible, anaphora only to expense in the immediately preceding request); `how should subsequent changes be measured` (measure, only to investment in immediately preceding request). Closed syntactic variations of heads are permitted when published, not inferred from test outcomes.

Declared subject identities and bounded aliases:

- CPF relief: personal tax relief on/for compulsory CPF contributions; personal tax relief on compulsory CPF; CPF relief for employees. `employees` means EMPLOYEE unless `I`/`they` explicitly fixes the claimant as INDIVIDUAL. `individual income tax relief for compulsory CPF` and `individual personal tax relief claim for compulsory CPF contributions` are equivalent issue-subject aliases for the original retained defect. No employer contribution synonym.
- Relief overview: personal tax reliefs; individual tax relief categories. Overview with `including CPF relief for employees` has scope OVERVIEW and mandatory `CPF_EXAMPLE`; the example facet cannot satisfy `OVERVIEW`.
- CPF contributions: CPF / CPF contributions with explicit employee/employer role. Coordinated calculation `how much CPF do the employee and employer contribute` yields two role-specific outcomes sharing a span. Employer only remains one. Salary prefix does not request rates.
- Private expense corporate tax treatment: contextual holiday paid for director and recorded travel expense. Private qualification required; generic deduction/motor car identities not equivalent.
- Foreign dividend corporate tax treatment: dividend from subsidiary in a declared foreign country (initially Thai/Thailand); foreign qualifier required. Domestic dividend not equivalent.
- Corporate tax residency: company tax resident under Singapore tax rules; general rule, not case-specific eligibility.
- Nonresident royalty WHT: general Singapore withholding-tax rules for company royalties to non-resident/nonresident company; both royalty and nonresident qualifiers required. Resident-only or another payment type not equivalent.

Context productions are anchored, bounded fact frames with captures: `For someone earning SGD <amount> a month,`; `Our Singapore company paid SGD <amount> for the director's private holiday and recorded it as travel expense.`; `Our Singapore company received a dividend from its <foreign-country> subsidiary in the current year.`. Amount grammar accepts nonnegative decimal amounts with correctly grouped commas. They own fact spans only. Context-reference treatment requires the appropriate preceding fact frame; absence, ambiguous references or contradictory modifiers yield UNCERTAIN. Captured private/foreign qualifiers must appear in the resulting outcome identity and be checked on the semantic observation. `what is its corporate income-tax treatment` is case-specific private treatment only under the private context; `explain the company's Singapore corporate income-tax treatment for this receipt` is foreign-dividend treatment only under the foreign context.

Special productions: fund manager `need a CMS licence or qualify for an exemption` is one ALTERNATIVE_DECISION with LICENCE, EXEMPTION and DECISION_RELATION facets. Investment `be FVPL or FVOCI` is one ALTERNATIVE_DECISION with FVPL, FVOCI and DECISION_RELATION, followed by independently requested measurement where present. Interaction `how <employer CPF contributions> affect <personal CPF tax relief>` is one INTERACTION with both participants and RELATION. Independent explain-rule issues cannot cover relation or decision facets merely by listing the participants. Initial production variants are bounded, published and compositional; genuinely unknown phrasing remains UNCERTAIN.

Coverage compatibility is exact by subject identity, population, operation and scope. An issue may cover a subset of an outcome's required facets only if all those dimensions match; compatible issues collectively cover facets. Example positive many-to-many: two distinct overview issues each cover different required facets of case06 (OVERVIEW and CPF_EXAMPLE), both scoped OVERVIEW. An issue with multiple bindings can represent two explain-rule outcomes only if it explicitly carries independently checked descriptors for each; an issue-wide subject or whole-question span alone cannot satisfy both. An issue descriptor uses bounded subject text plus the required dimensions; the derived subject identity, not a model-owned ID, is compared. A descriptor assigned twice redundantly to the same facet fails precision. Split issues with disjoint facets are legitimate. Invalid structure means UNCERTAIN; well-formed but wrong dimensions or unsupported extra issue means INCOMPLETE.

Clarifications: case03 is interpreted as eligibility/claimability, with salary context; its broad `what can they claim` remains an acknowledged natural-language ambiguity. The bounded production accepts this head in the declared CPF-relief phrase, but makes no amount inference. An explicit `how much relief` must select CALCULATE. Case18 must preserve deadline versus obligation facets. Case19 must preserve the decision relation. Cases11/12 require case facts later in application, even if representation is COMPLETE. Correct observations for case16 do not change unsupported support status. All such decisions are synthetic representation expectations, not tax conclusions.

Additional controls before feasibility approval: amount-head substitution in case03; context qualifier substitutions (private/business, Thai/Singapore); complete alternative participants without relation; split overview facets; one observation with two valid descriptor bindings; malformed facet sets; novel combination of already supported head/subject productions absent from fixture inventory; emoji prefix/unsupported suffix, over-limit input and deliberately invalid span offsets.

Binding descriptors carry their own subject text, population, operation, scope and represented facets. Mandatory facets include COMPULSORY where the raw request qualifies contributions as compulsory, GENERAL for the general rules in 13–15/23/24, and PRIVATE/FOREIGN where contextual facts determine identity. Interaction uses directional facet EMPLOYER_CONTRIBUTIONS_AFFECT_PERSONAL_RELIEF; the inverse is not equivalent. All span claims must be contained within the independently identified request's span(s). A whole-query span is valid for a single request, but never validates unrelated bindings. Coordinated requests may legitimately share the same span.

Empty valid bindings or empty represented facets are well-formed omissions (INCOMPLETE with complete raw parse). Missing required binding fields, nonarrays, duplicate IDs, invalid facet types or invalid spans are malformed (UNCERTAIN). A duplicate well-formed descriptor for the same outcome/facet is a precision failure (INCOMPLETE). Unknown raw inventory takes precedence as UNCERTAIN, retaining independently established omission/mismatch diagnostics. Provider failure or legacy V2 without sufficient descriptors is UNCERTAIN irrespective of old coverage flags. In case26 the explicit later CPF request may be retained as a partial observation, but negated/contrasting text leaves the overall inventory UNCERTAIN; it must not be interpreted as a positive overview.

Unknown prefix, infix, suffix and qualifiers must all be tested. Add a broad overview with two examples as UNCERTAIN unless the grammar independently recognizes both example facets; never silently discard the second. Add held-out positive compositions for each declared connector and changed coordinated populations. These controls are outside the 28 base oracle cases and must not feed the runtime grammar.
